# 余光：本地录像、音频与基础事件检测

状态：用户已审阅并明确选择“按这份设计实现”，2026-10-20。实现与自动验证记录见[验收记录](../../VALIDATION.md)。

## 已确认的目标

用户要把现有余光用于离线看家／看宠物，在手机或可用的外置 SD 卡保存录像。

- 连续循环录像与事件录像都提供，可以切换。
- 麦克风默认关闭；开启后支持声响检测、本地录像音轨及 RTSP 音轨。
- 这轮先做画面变动与声响检测；人物、猫狗识别后续再加。
- 保留 Android 4.4（API 19）支持及现有四向自动方向、方向锁定、校准、完整预览和裁剪遮罩。
- 视频录像和推流都使用已选输出尺寸、方向与裁剪内容。
- 检测、编码、保存均在设备运行，不依赖外网、账号或云服务；局域网推流继续可选。

## 建议的用户体验与默认规则

### 录像

新增「本地录像」入口，录制模式为关闭、连续循环、事件录像，初始关闭。
选择录像功能和目标目录后，由现有运行按钮启动采集；增加「仅本地」输出方式，
使用户能够录制而不启动 RTSP／HTTP 服务。

- 连续模式：持续保存，默认每 5 分钟封装一个 MP4；检测到事件时给对应时间段做标记。
- 事件模式：保留触发前约 5 秒、最后一次触发后约 15 秒的片段；连续触发合并。
- 预录长度受最近关键帧和 8 MiB 内存上限约束，界面不承诺精确到毫秒；长事件同样遵守分段设置。
- 根据用户后续要求，独立设置页提供分段时长（10–3600 秒）、单段大小上限（16–2048 MiB）、
  总额度（1–1024 GiB）、最低剩余空间（64–16384 MiB）、保留天数（0 为不限）、
  循环覆盖／停止策略、事件预录（0–30 秒）和延录（1–600 秒）、独立录像声音开关。
  时长到达后在下一关键帧切段；接近大小上限时提前分段，无关键帧时暂停，避免持续超限。
  默认 5 分钟、256 MiB 单段、2 GiB 总额、256 MiB 保留空间、5 秒预录／15 秒延录。
- 录制开始、停止、切换镜头／分辨率时明确标出状态。普通旋转沿用现有像素校正。
- 正常结束后才把 MP4 标记为可播放；异常断电可能损失正在写的一段，不能保证恢复。

新增录像列表，显示时间、时长、大小、事件原因；支持播放、导出、删除和锁定片段。
锁定表示不参加循环清理，用户仍可明确删除。播放使用本地文件，不访问外网。

### 手机／外置 SD 卡

通过系统暴露的应用专属存储目录枚举可写目标，支持手机存储与可用的 SD 卡。
Android 4.4 上不保证任意 SD 目录可写；未知卷只标记为「外置存储」和路径，
不把数组第二项直接认定为可移除 SD 卡。

- 首次默认选择手机存储，可切换到可写的外置目标；写入前试写并检查所在卷状态。
- **应用专属目录中的录像会随卸载应用删除。** 在选择存储位置处明确说明，
  并提供导出，供用户保存到系统文件选择器选定的位置。
- 首版不提供持续写入任意文件夹的功能。Android 5+ 的目录授权可后续增加，
  避免 Android 4.4 与新系统表现不一致，以及旧版 MP4 封装的暂存复制负担。
- 建议默认录像容量上限 2 GiB，可调整；保留至少 256 MiB 可用空间，并限制单段大小。
- 连续和事件模式都遵守容量上限：循环模式仅清理当前目标中本应用登记的已完成、未锁定片段，
  从最旧开始；不删除用户其他文件，不删除正在写入或已锁定的片段。
  停止策略不自动删除任何片段；保留天数也只在循环模式执行。
- 无可清理空间、SD 卡拔出／只读或写入失败时暂停录制并显示原因，已有推流继续。
  不悄悄切换到手机存储。恢复同一存储目标后，用户可重试录制。
- 录像索引与文件一一对应；删除和残留清理仅针对登记目标；导出只读取登记文件，
  写入用户通过系统选择的目的地。

### 声音

当前 1.2.1 没有麦克风采集或音频推流。本轮新增统一麦克风开关，默认关闭；
只有用户启用相关功能时申请权限并启动采集。

- 一个麦克风采集源，分别供声响检测和 AAC 编码使用，避免抢占同一设备。
- 开启后 RTSP 使用 AAC 音轨，本地 MP4 可独立选择是否保存声音；
  声响检测仅在其独立开关启用时触发事件。
- 没有权限、麦克风被占用或音频编码失败时显示实际状态，不把无声文件标成有声。
- 麦克风切换会结束旧 MP4 并重建 RTSP 会话，从新关键帧建立新轨道。
  音频采集／编码故障结束当前采集会话并明确提示；用户关闭麦克风后可恢复无声运行，
  不在后台静默降级。存储写入故障仍单独处理，不中断推流。
- 视频与音频使用同一单调时钟，处理开始时差和分段时间戳。
- 麦克风关闭后不继续采集音频，也不再执行声响检测。
- MJPEG 网页仍为无声图像。本轮不新增网页音频通道、WebRTC、对讲或云端播放。
- 内置观看页提供选择有声 RTSP 的入口；不能继续默认选 MJPEG 却让用户以为有声音。
- 系统限制下不能保证开机后无交互就启动麦克风；后台启动失败应提示回到应用开启。

### 基础检测

画面变动检测分析裁剪后的实际输出范围，低分辨率、低频采样，不阻塞采集或推流。
以帧差／背景统计识别变化，提供低／中／高灵敏度。

- 持续达到阈值才触发，配合冷却与事件合并，减少瞬时噪点和亮度变化带来的重复记录。
- 切换镜头、尺寸、方向或校准后重建背景并短暂预热，避免把界面操作当成事件。
- 不把普通画面变化标为「人」或「宠物」；树影、灯光等仍可能引起误报。

声响检测分析本机 PCM 的相对能量及持续时间，提供灵敏度与冷却。
它只判断明显声音变化，不承诺识别说话、犬吠或具体声源；
未校准的手机麦克风也不显示为精确的环境声压分贝。

检测开关独立，可启用画面、声响或二者。事件记录包含触发原因与时间。
第一版分析整个输出画面；可绘制检测区域、忽略区域和定时布防列入后续候选。

## 模块设计

沿用单摄像头和现有 H.264 编码器，避免为录像重复采集／编码。

1. 相机 → 现有方向、裁剪变换 → 视频编码；检测旁路读取缩小的亮度样本。
2. 麦克风 → PCM → 声响检测与 AAC 编码。
3. 编码数据同时分发至 RTSP、预录缓冲和录像器；这些消费者生命周期独立。
4. 录像器使用有界队列与独立磁盘线程。慢 SD 卡或队列溢出时结束／放弃当前段并明确报错，
   不能任意丢弃依赖帧后继续声称该段完整。
5. 录制状态、事件元数据与文件目录由独立存储模块管理，UI 只读取状态和提交设置。

### 视频编码与 MP4

`H264Encoder` 需输出真实 `MediaFormat`、CSD 与样本标志，而不仅是 RTSP 所需 SPS/PPS。
`MediaMuxer` 从 API18 可用，API19 可写路径形式的 MP4。
普通编码配置数据不作为视频样本写入；每段从关键帧开始，轨道格式就绪后启动封装，
音视频以共同段起点归零。分辨率／镜头重配先结束旧段，再建立新轨道。
老系统封装不支持 B 帧，编码配置与验证需覆盖这一限制。

正常停止时先终止新采样，排空必要编码输出和录像队列、完成封装，再释放资源。
服务代际检查沿用现有机制，迟到的回调不能写入新会话或停止新会话。

### RTSP 音频

当前客户端状态只有一条视频轨，增加音轨需要按轨管理 SETUP、端口／交错通道、
序列号、SSRC、RTP 时钟及 RTCP Sender Report。不能只在 SDP 添加一行音频描述。

增加 AAC SDP、音频 RTP 封包与双轨 RTP-Info，保留现有 TCP/UDP 视频客户端兼容性。
麦克风关闭时 SDP 不宣告不存在的音轨。测试应覆盖仅视频、双轨、不同 SETUP 顺序、
断连和服务重启。

## 验证与交付

- 自动测试：画面/声响阈值、方向变化预热、事件预后录合并、容量清理与锁定保护、
  SD 失败状态、关键帧起段、音视频时间戳及有界队列行为。
- 网络测试：真实 RTSP 请求、双轨 SDP/SETUP/PLAY、AAC RTP 头、TCP/UDP 路由和重启回收。
- 保留现有几何、相机、生命周期、HTTP/MJPEG、网页重连回归。
- 构建与 Android lint；验证安装包签名、版本和 API19 边界。
- 真机待验收：MP4 播放、音画同步、第三方 RTSP 播放器、SD 卡拔插／满盘、
  断电后的已完成片段、长时间运行和不同 Android 的后台限制。
- 发布新版 APK 到原 dist 目录，并推送现有私有 GitHub；只有验证过的结果写入发布说明。
